## 目标
将当前 `stage1-tools` 分支整理成一个可运行、可离线验证的 Stage 1 最小版本，同时保留 `stage0_hello_agent/` 不变。

## 修改范围
1. `stage1-tools/tools.py`
   - 删除未使用且不在 requirements 中的 `anthropic`、`huggingface_hub`、`jinja2`、`torch` 等导入。
   - 保留并完善 `read_file`、`write_file`、`edit_file`。
   - 增加 `list_files`，使 Agent 的系统提示词与实际工具一致。
   - 实现 `glob` 和 `grep`，统一返回字符串，并对不存在路径、非文本文件、读取异常返回明确错误。
   - 暂不将 `bash` 放进可用工具注册表；保留实现位置或明确未启用，避免权限系统完成前暴露任意命令执行能力。
   - 补全 Anthropic `TOOLS` schema，保证每个已启用工具都同时存在于 `TOOLS` 和 `TOOLS_FUNCS`，并且参数名、必填字段一致。

2. `stage1-tools/agent.py`
   - 删除无关导入、重复的工具定义和重复的 `run_agent`。
   - 保留唯一一份完整 Agent Loop。
   - 统一使用 `execute_tool_call`，修复当前 `excute_toll_call` 拼写错误。
   - 在执行工具前做工具名、参数类型、必填参数和未知参数校验。
   - 工具异常统一转换为 `tool_result`，失败时设置 `is_error: True`。
   - 对工具结果做长度截断，避免单个文件或搜索结果撑爆上下文。
   - 检查 `stop_reason`，识别 `max_tokens` 截断。
   - system prompt 只引用实际注册的工具。

3. `stage1-tools/README.md`
   - 更新为 Stage 1 的实际目录和运行方式。
   - 说明当前启用的工具，以及 `bash` 暂未启用的原因。
   - 增加离线工具测试命令和真实 API 运行命令。

4. 新增 `stage1-tools/test_tools.py`
   - 不调用模型，直接验证工具函数和执行器：读写文件、唯一文本替换、重复文本拒绝、glob、grep、未知工具、缺少参数、未知参数和结果截断。
   - 测试使用临时目录，不修改项目文件。

## 验证步骤
1. 用 `py_compile` 检查 `agent.py`、`tools.py` 和测试文件语法。
2. 运行 `python stage1-tools/test_tools.py`，验证工具逻辑不依赖 API key。
3. 如果当前环境允许安装依赖，则创建/使用项目 `.venv` 并安装 `requirements.txt`；否则明确报告真实 API 运行未执行。
4. 检查 `git diff --check`、`git status`，确认没有 `.env`、`.idea` 或缓存文件被加入。
5. 不自动提交或推送，保留修改供你审阅。
